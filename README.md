# RAG-пайплайн для Альфа-Банка

Основная логика собрана в ноутбуке **`workflow.ipynb`**. Его нужно запускать по шагам сверху вниз.

---

## Кратко о главном

1. **Qdrant как векторное хранилище**  
   Есть 3 коллекции `rag_chunks_v2`, `rag_chunks_v2_pprd` и `rag_chunks_v3` в Qdrant

2. **Infinity API для моделей**  
   - `/embeddings` — эмбеддинги на базе `BAAI/bge-m3`
   - `/rerank` — реранкинг с помощью `BAAI/bge-reranker-v2-m3`

3. **Гибридный поиск**  
   Поиск идёт сразу по dense-векторам и по BM25, а результаты объединяются через RRF. Поверх этого ещё раз доранжируем документы

4. **LLM над retrieve**  
   LLM сначала переписывает пользовательский запрос в хороший поисковый, затем вызывает `retrieve` и уже по найденному контексту формирует финальный ответ для пользователя

---

## Коллекции в Qdrant

В проекте используются три версии коллекции с чанками документов:

- **`rag_chunks_v2`**  
  Векторка с 1-го тура.  
  Dense-вектор собирается из конкатенации:
  - `chunk_text`  
  - `doc_entities`  
  - `doc_tags`  
  - `title`  

  Дорого богато, но шумновато

- **`rag_chunks_v2_pprd`**  
  Та же логика текстов, но:
  - BM25 переиндексирован на очищенных и нормализованных данных;

- **`rag_chunks_v3`** (финальная)  
  Новая версия:
  - BM25 построен заново;
  - dense-векторы считаются **только по** `chunk_text + title`. 

Переключение коллекции делается через переменную `COLLECTION_NAME`

## Основной пайплайн

Все шаги реализованы в `workflow.ipynb`:

1. **Препроцесс запросов**  
   Цель — сделать запрос максимально понятным для поиска, не ломая смысл

2. **Подготовка датасета вопросов**  
    `process_csv(...)` - очень много регулярок

3. **Гибридный поиск в Qdrant**  
    `hybrid_search(...)`

4. **Реранкинг (BGE-reranker)**  
   `rerank_docs(...)`

5. **Инструмент `retrieve` для агента**  
   - принимает текстовый запрос,
   - внутри вызывает гибридный поиск + реранкер,
   - возвращает аккуратно отформатированный контекст (source + content) в виде текста

6. **LLM и промпты**  
   - Первый промпт — переписать пользовательский запрос в хороший поисковый запрос для базы знаний банка.  
   - Второй промпт — на основе запроса и контекста от `retrieve` сформировать короткий, точный ответ

7. **Асинхронный запуск по всем вопросам**  
    `run_agent_async`, `run_multiple_queries_parallel` и `run_in_notebook`:
   - прогоняют все запросы из `questions_ready.csv` параллельно;
   - контролируют `max_concurrent` и таймауты;
   - пишут результаты в CSV (`submission_*.csv`)

8. **Финальный submission**

1. Поднять Qdrant и Infinity API
2. Открыть `workflow.ipynb`.
3. Запускать ячейки по порядку сверху вниз:
4. В конце проверить финальный CSV с ответами и при необходимости использовать его для сабмита/продакшн-интеграции.
